# Movie Rating Predictor

This project predicts whether a MovieLens 20M user will rate a movie at least
4 stars. It is an offline production-development (PRD) system built around
point-in-time-correct features that can later be reproduced by an online
serving path.

## Current PRD status

The canonical feature contract contains 30 predictors: the historical
17-feature rating/catalog baseline, five additional unique rolling-movie
columns (alongside the existing 30-day count), and eight Genome features. The
last trained **`xgboost_genome_prd_v1`** artifact retains its frozen 25-feature
contract until the canonical notebooks are rerun. Its machine-readable source of truth is
[`models/prd/prd_model_manifest.json`](models/prd/prd_model_manifest.json).
Notebooks are the primary training and evaluation workflow; technical metadata is
generated by [`src/training/build_prd_manifest.py`](src/training/build_prd_manifest.py);
promotion remains a human decision; and
[`src/training/prd.py`](src/training/prd.py) validates the generated pointer.
The executable contract is [`src/training/prd_config.py`](src/training/prd_config.py).

The target is `highRating = (rating >= 4.0)`. Every history-dependent feature
uses only events with `event.timestamp < prediction_timestamp`. Events sharing
a timestamp are scored from the same pre-batch state and applied only after the
complete batch is scored. Movie catalog data and undated Genome vectors use
documented frozen-snapshot assumptions; user-dependent Genome aggregates remain
strict-prior.

The model is an offline temporal baseline, not evidence of online business
lift. Online state and serving work have not started.

## Data

The repository expects the six MovieLens 20M sources (`rating`, `movie`,
`link`, `tag`, `genome_scores`, and `genome_tags`) under `data/raw/`. Raw CSVs,
processed Parquet files, and materialized feature datasets are local generated
data and are ignored by Git.

The main pipeline converts validated source CSVs to typed Parquet, constructs
canonical entities, replays timestamp batches to materialize leakage-safe
features, and trains or validates the model against fixed calendar splits:

- train: before 2012-01-01;
- validation: 2012-01-01 through 2013-12-31;
- test: 2014-01-01 onward.

The complete temporal semantics are in
[`docs/TEMPORAL_CONTRACT.md`](docs/TEMPORAL_CONTRACT.md).

Although all six raw sources are converted to Parquet, the current 30-feature
materializer reads only `ratings.parquet`, `movies.parquet`, `links.parquet`,

feed the current PRD model.

## Main result

On the 846,774-row 2014+ test partition, the PRD model achieved:

| Metric | Result |
|---|---:|
| PR-AUC | 0.809925 |
| ROC-AUC | 0.820356 |
| Log loss | 0.517775 |
| Brier score | 0.173378 |
| ECE, 10 uniform bins | 0.023489 |

It improved PR-AUC, ROC-AUC, log loss, and Brier score over the frozen
17-feature baseline in every test quarter from 2014Q1 through 2015Q1. See the
[`Genome promotion record`](docs/MODEL_PROMOTION_GENOME_V1.md) for the complete
comparison, provenance, tradeoffs, and limitations.

```text

models/experiments/   Controlled experiment evidence

src/entities/         Canonical entity contracts and relational builders
src/features/         Catalog, temporal, baseline, Genome, and materialization logic
src/state/            Point-in-time state, checkpoint, and replay implementation
src/training/         Canonical config, manifest generation, and validation
src/serving/          Reserved for future online serving work
tests/                Unit, temporal, replay, materialization, and PRD contract tests
```

The immutable `models/experiments/genome_experiment_v1/` bundle explains why
the 25-feature model was selected. Canonical notebooks write
`models/prd/xgboost_genome_prd_v1.model.json` and
`models/prd/xgboost_genome_prd_v1.results.json`, then regenerate the manifest.
That notebook-produced artifact is the current PRD pointer; the experiment
directory remains selection evidence, not the training output location.

Feature contracts are explicit in `src/training/feature_contracts.py`:
`BASELINE_17` and `GENOME_25` freeze historical names, order, dtypes,
nullability, and roles; `PRD_30` defines current training inputs. Historical
CLIs select the frozen contracts even when reading compatible columns from a
newer feature artifact. Current model evaluation is recorded separately from
the frozen comparison; approved rolling features do not require model lift.

The training layer stays small and notebook-first:

- `prd_config.py`: canonical executable PRD contract;
- `build_prd_manifest.py`: derive technical metadata from saved artifacts;
- `prd.py`: validate the generated manifest, artifact, and contract;
- `modeling.py`: scoring helpers plus optional historical reproduction utilities;
- `train_prd.py` / `compare_genome.py`: historical auditor reproduction CLIs,
  not the primary training interface.

## Setup and reproduction

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

# Build typed Parquet inputs from data/raw/.
python -m src.data.build_parquet

# Materialize the canonical 30-feature dataset.
python -m src.features.materialize
```

### Validate or retrain the model

The committed artifact and manifest still validate against their frozen
25-feature contract. After regenerating the feature artifact with the new
30-feature contract, run the canonical notebooks before validating the newly
trained model and regenerated manifest:

```bash
python -m src.training.prd
python -m src.training.build_prd_manifest --check
pytest -q -ra -W default
```

`prd` validates the pointer, booster, evaluation evidence, and local v2
metadata. `--check` regenerates technical metadata in memory and compares it
with the committed manifest; it does not choose a model or overwrite the
pointer.

### Retrain with notebooks

Run the canonical notebooks in order after the shared data steps above:

1. `notebooks/model/genome_prd_v1/01_training_dataset.ipynb`
2. `notebooks/model/genome_prd_v1/02_temporal_splits.ipynb`
3. `notebooks/model/genome_prd_v1/03_xgboost_training.ipynb`
4. `notebooks/model/genome_prd_v1/04_model_evaluation.ipynb`
5. `notebooks/model/genome_prd_v1/05_model_artifact_and_manifest.ipynb`

They validate the v2 dataset, audit configured splits, train and save the
canonical booster, save evaluation results, and derive and validate the
manifest. `status = "PRD"` is emitted only when promotion is requested
explicitly. After the notebooks finish, rerun the validation commands above.
Reproducibility assumes the same data, environment, seed, and code; XGBoost
does not guarantee byte-identical serialization across library or platform
versions.

### Optional historical CLIs

`python -m src.training.train_prd` retrains the promoted model into a separate
reproduction directory and is intentionally not part of routine validation.
`python -m src.training.compare_genome` likewise reproduces the historical
two-model experiment outside the immutable evidence directory. Both are
optional historical CLIs and computationally expensive.
